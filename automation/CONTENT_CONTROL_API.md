# R/Form Content Control API v0.3

Защищённый шлюз между `RFORM_MASTER_DATA_v1` и приложением «Управление контентом». Он сохраняет чтение данных из версии 0.1 и добавляет только четыре разрешённых действия владельца.

## Разрешённые действия

| Действие в приложении | Код | Изменяемые поля |
|---|---|---|
| Утвердить | `APPROVE` | `Approval_Status`, `Pipeline_Status`, `Preview_Review_Status` |
| Вернуть на доработку | `RETURN_FOR_REVISION` | `Approval_Status`, `Publication_Status`, `Pipeline_Status`, `Preview_Review_Status` |
| Поставить на паузу | `HOLD` | `Publication_Status`, `Pipeline_Status` |
| Готово к публикации | `READY_TO_PUBLISH` | `Publication_Status=PLANNED`, `Pipeline_Status=READY_FOR_PUBLICATION`, `Preview_Review_Status=REVIEWED` |

Шлюз не устанавливает `SCHEDULED`, `PUBLISHING` или `PUBLISHED`, не обращается к Telegram и не содержит токена Telegram. Поэтому действие «Готово к публикации» не запускает автопубликацию.

## Защита записи

- общий секрет остаётся только в свойствах Apps Script и Streamlit Secrets;
- HMAC-подпись связывает время, nonce, `Action_ID`, код материала, действие и хеш комментария;
- запрос действует 5 минут;
- повтор nonce блокируется;
- `Action_ID` обеспечивает идемпотентность;
- можно изменять только существующий уникальный `Content_ID`;
- закрытые материалы изменять нельзя;
- перед «Готово к публикации» сервер повторно проверяет все условия готовности;
- комментарий обязателен для возврата на доработку и постановки на паузу;
- пользовательский комментарий нейтрализуется от формул Google Таблиц;
- запись выполняется под блокировкой; при ошибке статусные поля откатываются.

## Журнал действий

При первом подтверждённом действии шлюз автоматически создаёт лист `CONTENT_ACTION_LOG`. В журнал записываются:

- идентификатор и время действия;
- код материала и действие;
- комментарий;
- изменённые поля;
- предыдущие и новые значения;
- nonce и результат выполнения.

## Обновление существующего Apps Script

1. Открыть проект `RFORM_CONTENT_READ_API_v0_1`.
2. Полностью заменить содержимое `Code.gs` кодом из `content_control_api_v0_3.gs`.
3. Нажать **Сохранить**.
4. Запустить `rformContentApiPreflight`.
5. Проверить: `ok: true`, `version: 0.3.0`, `content.action` присутствует в `capabilities`.
6. Открыть **Развернуть → Управление развертываниями**.
7. Нажать **Изменить**, выбрать **Новая версия** и нажать **Развернуть**.
8. Сохранить существующий URL `/exec`; секрет менять не требуется.

После обновления приложение должно показать режим `КОНТРОЛИРУЕМЫЕ ДЕЙСТВИЯ · v0.3`. Первый приёмочный тест следует проводить на отдельной тестовой строке, а не на будущем реальном материале.
