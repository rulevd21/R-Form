# R/Form · Управление контентом v0.5.3

Приватная русскоязычная панель, которая сама находит новые тренировки, сопоставляет их с неопубликованным контентом и оставляет владельцу только выбор готовой публикации.

## Главное изменение v0.5.3

Готовые редакционные материалы со стадией `OWNER_FINAL_PREVIEW` теперь имеют
приоритет во вкладке **«Сегодня»**. Если Weekly уже включает отдельные тренировки,
они отмечаются через `COVERS:` в `Proof_Source` и больше не возвращаются как
отдельные предложения.

Согласование готового материала выполняется одной кнопкой: текущий текст и уже
подготовленный визуал утверждаются, материал переводится в `SCHEDULED` и
передаётся существующему Telegram Autopost.

## Возможности v0.5.2

Целевой маршрут владельца остаётся коротким:

1. открыть приложение;
2. выбрать один из готовых комплектов «текст + визуал»;
3. при необходимости изменить текст или сформировать другой визуал;
4. нажать **«Согласовать и отправить»**.

Приложение автоматически:

- читает закрытые записи `TRAINING_SESSIONS`;
- находит последнюю тренировку, для которой ещё нет согласованной публикации;
- проверяет текущую очередь `CONTENT_QUEUE`;
- рекомендует обновить тематически подходящий плановый материал, чтобы не плодить дубли;
- одновременно готовит альтернативный самостоятельный отчёт;
- использует только фактические значения плана, результата, RIR, техники, боли и объёма;
- автоматически формирует три мобильных варианта визуала 1080×1350 в системе R/Form;
- позволяет исправить текст прямо в предпросмотре и циклически выбрать другой визуал;
- после явного согласования сохраняет выбранный PNG на Google Drive и передаёт комплект существующему Telegram Autopost.

Для тренировки C от 21.08.2026 рекомендуемый вариант обновляет плановый пост о дневниках без перегруза. Альтернатива создаёт отдельный материал **«21.08.2026 · Тренировка C · Итоги и решение»**.

Навигация содержит только три раздела:

- **Сегодня** — единственная точка выбора и согласования;
- **План** — только будущие публикации и объяснение, когда они появятся в работе;
- **Система** — диагностика для обслуживания.

Опубликованные, заменённые, просроченные и технические строки автоматически
исключаются из рабочего интерфейса. Они сохраняются в мастер-таблице как журнал и
защита от дубликатов, поэтому физическое удаление не требуется. Старые предложения
из `DATA_EVENTS` больше не подставляются во вкладку **«Сегодня»**.

## Безопасность данных

Исходные поля системы выявления событий остаются неизменяемыми из интерфейса. Редактор пишет только в отдельные owner-поля:

- `Owner_Fact`
- `Owner_Angle`
- `Owner_Note`
- `Owner_Media_URLs`
- `Owner_Media_Folder_URL`
- `Owner_Review_Status`
- `Owner_Updated_At`

Все операции подписываются HMAC, имеют короткое окно действия и отдельный `Action_ID`. Перед согласованием шлюз повторно проверяет, что исходная тренировка не изменилась. Повторная отправка уже запланированного или опубликованного материала запрещена.

Content Control API не содержит Telegram-токен и не вызывает Telegram. Только явное нажатие **«Согласовать и отправить»** сохраняет точный выбранный текст и визуал, устанавливает `SCHEDULED` и `AutoPost_Allowed=YES`; отправку выполняет отдельный ранее установленный Telegram Autopost.

## Возможности API v0.5.3

- `content.read`
- `content.action`
- `event.review`
- `event.decision`
- `event.media`
- `training.read`
- `publication.propose`
- `publication.visual`
- `publication.approve_schedule`

Обычные действия и предложения событий не могут запускать публикацию. `SCHEDULED` разрешён только отдельной подписанной операции согласования готового текста.

## Обновление существующего Apps Script

Используйте `../../automation/content_control_api_v0_4.gs` вместо v0.3 в существующем standalone Apps Script-проекте Content Control.

Важно:

1. Не создавайте новый секрет. v0.5 использует то же Script Property `RFORM_CONTENT_API_SECRET`.
2. Замените действующий код целиком; не оставляйте два `doPost/doGet` одновременно.
3. Выполните `rformContentApiV04Preflight()` и разрешите доступ к Google Drive, если Apps Script запросит его.
4. Результат должен содержать `ok: true`, `version: 0.5.3`, пустые списки missing-полей и capability `publication.queue_approve_schedule`.
5. Обновите существующий Web App deployment новой версией. URL `/exec` должен остаться тем же.
6. Streamlit Secrets менять не требуется, если URL и секрет не изменились.

## Локальный запуск

```bash
cd apps/content-control
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

Без `secrets.toml` приложение запускается в режиме `DEMO / FIXTURE`.
