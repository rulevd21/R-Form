# R/Form Owner Workspace v1.1.0 — кандидат для установки

Дата: 08.10.2026. Запрос владельца: ID287, продолжение требований ID284–286.

## Результат и границы

Основной интерфейс — существующий Telegram Owner Bot. Content Control остаётся
вспомогательной панелью. CONTENT_QUEUE — единственная очередь; Content API —
единственный писатель её переходов; существующий Telegram Autopost —
единственный транспорт публикации.

Версии кандидата: Owner Bot **1.1.0**, Content API **0.6.0**.
Streamlit остаётся **0.5.6**. Изменений Training, Detector и Autopost нет.
Кандидат не установлен. Боевые строки, секреты, разрешения, триггеры и публикации
при подготовке не изменялись.

## Сценарии

### Обзор и поиск

/queue, /start, /help открывают «В работе», «Отложено», «Опубликовано».
В списке 5 материалов на страницу. /search ищет название, дату или Session_ID
во всех трёх разделах. Опубликованная карточка содержит ссылку на пост
и не предлагает редактирование.

Кнопки содержат короткий хеш Content_ID; сервер заново разрешает точный объект.
Все owner-действия ограничены связанными user ID + private chat ID.

### Ручной текст и версии

1. Открыть карточку → «Изменить текст».
2. Отправить полный новый текст, максимум 4096 символов.
3. Бот показывает исходный и предлагаемый текст.
4. «Сохранить эту версию» действует только для просмотренной текущей ревизии.
5. Content API сверяет source hash, записывает текст и журнал предыдущих/новых значений,
   сбрасывает review/approval и проверяет readback.
6. История последних 10 сохранений позволяет выбрать старую версию как предложение,
   проверить и сохранить новой ревизией. История не удаляется.

Несохранённые правки находятся в CacheService до 6 часов, могут исчезнуть раньше
при вытеснении кэша. Бот сообщает об истечении. Это временное состояние интерфейса,
не второй datastore. Сохранённый текст и история находятся в SoT.

### Фото с телефона

1. Открыть карточку → отправить Telegram-фото или альбом.
2. Бот скачивает JPEG через собственный Telegram token и передаёт байты подписанному API.
3. API сохраняет приватный staged файл, связанный с Content_ID и source hash.
   Canonical визуал на этом шаге не меняется.
4. В «Фото и порядок» доступны удалить / раньше / позже / заменить.
5. «Просмотр правок» показывает выбранный порядок фото.
6. Сохранение создаёт новую приватную папку с точным комплектом card-01_v01.jpg и т.д.
   Предыдущая папка сохраняется. 0 фото → TEXT_ONLY, 1 → PHOTO_CAPTION, 2–10 → ALBUM_CAPTION.

Лимиты: JPEG/PNG в API, Telegram-фото передаются JPEG, до 5 МБ на фото, до 15 МБ
на комплект, до 10 фото. Файлы-документы, видео и автоматическая обработка изображений
не входят в эту версию. Никакого публичного Drive sharing не добавлено.

### Отложено

«Отложить» устанавливает HOLD, снимает согласование и расписание.
Материал остаётся там до ручного «Вернуть в работу».
Дата рассмотрения задаётся ДД.ММ.ГГГГ ЧЧ:ММ по Москве; по умолчанию напоминание
включено, суффикс «без напоминания» отключает его.
Напоминание приходит только владельцу и никогда не переводит HOLD в публикацию.
При неопределённом результате отправки напоминание автоматически не повторяется.

### ИИ-правки — подготовлен путь, автоматический исполнитель отсутствует

«Поручение ИИ» сохраняет OWNER_AI_REQUEST в существующем CONTENT_ACTION_LOG.
Запрос содержит точный Content_ID, source_hash и инструкцию.
R/Form Content Orchestrator может подготовить предложение через подписанный
owner_workspace / ai_proposal с request_id, тем же source_hash и новым текстом.
Предложение сохраняется только в журнале, canonical Telegram_Text не меняется.
Следующий существующий poll уведомляет владельца. Владелец смотрит правки и сохраняет.
Устаревшее предложение или повторная выдача для того же запроса отклоняются.

**Это не подключённая автоматическая генерация ИИ.** В текущей архитектуре нет
проверенного always-on исполнителя модели. До его подключения бот честно сообщает
об этом. Новый платный API/сервис не создан. Эта часть остаётся открытым
интеграционным пунктом; не считать заявку в журнале выполненной ИИ-правкой.

### Черновик завершённой тренировки

Используется текущий rformOwnerBotV1Poll, без второго scheduler.
Перед чтением очереди poll вызывает signed owner_workspace / sync_training.
Content API читает SoT и создаёт максимум 3 новых коротких черновика за опрос.

Условия: CLOSED, непустой Completed_At, нет Duplicate_Flag, уникальный Session_ID,
есть Main_Result; тренировку не покрывает существующий объект/Weekly COVERS.
HOLD и опубликованные связанные объекты тоже защищают от повторного создания.
При включении все уже закрытые тренировки фиксируются baseline, старые посты не создаются.
Тренировка, которая была OPEN при включении, может закрыться позже и попасть в поток.

Текст: дата / тип, Main_Result, фактическая длительность, существующее Session_Decision
и #RForm_Training. Нет новых интерпретаций и обещаний. Текст длиннее 1200 символов
останавливает автоматическое создание и требует редакторского сокращения.
Автоматический черновик **не является рекомендацией публиковать каждую тренировку**:
сохраняется gate владельца, а уже покрытые тренировки исключаются.

Черновик получает READY / NOT_REQUIRED / NOT_READY / PLANNED /
OWNER_FINAL_PREVIEW / AutoPost_Allowed=NO / Publish_At пусто.
Fingerprint источника хранится в аудит-логе. Исправление исходной тренировки
блокирует prepare/approval до сверки фактов.
Ошибки записи помечаются OUTCOME_UNKNOWN; черновик блокируется и не повторяется автоматически.

### Финальный предпросмотр

Owner Bot показывает сохранённый текст и фотографии так же, как Autopost:
до 1024 символов — caption; длиннее — фото и отдельное сообщение.
Изменение текста/состава фото делает прежние кнопки согласования неактуальными.
Несохранённые правки блокируют согласование.
Только отдельное «Согласовать» передаёт точную проверенную версию в существующий Autopost.
Для фотографии проверяется также byte SHA256. Нового Telegram publisher нет.

## Макет

docs/owner-workspace-mobile.html — автономный интерактивный макет с вымышленными
данными, вкладками, поиском, редактором и локальной загрузкой фото.
Из макета нет сетевой записи, вызова ИИ или публикации.

## Проверки перед установкой

Offline harness эмулирует Sheets/Drive/Properties/Cache/Telegram.
Настоящий UrlFetchApp в тестах запрещён; Telegram отправки перехватываются.
Проверяются signed request, concurrency, idempotency, rollback/unknown, HOLD/reminder,
manual edit, AI proposal, photo ownership/order/versions, one session→one draft,
source freshness, callback limits, приватный доступ и существующий transport redirect.
Python tests проверяют совместимость Streamlit, включая gateway contract.

## Установка — отдельный следующий этап

По workflows-code-release.md production merge, замена Apps Script и deployment
требуют отдельного точного разрешения владельца. Подготовка кандидата его не заменяет.

1. Сохранить текущие версии/rollback исходники: API 0.5.7 и Bot 1.0.5.
2. Установить Content API 0.6.0 в **существующий** проект и обновить **существующий** deployment.
   Не менять API URL, HMAC secret, sheet schema или разрешения.
3. Read-only API preflight: version 0.6.0, capability publication.owner_workspace,
   required fields без пропусков, очередь/история сохранены.
4. Установить Owner Bot 1.1.0 в **существующий** проект и существующий deployment.
   Сохранить pairing, token и webhook secret. Не запускать Install/Enable повторно:
   Install по старому контракту отключает действия, Enable очищает sentState.
5. Read-only Bot preflight: version 1.1.0 / API 0.6.0, owner paired, один poll trigger,
   webhook без ошибки; все новые команды пока проверить при actionsEnabled=NO.
6. Не включать sync до согласованной baseline. При разрешённом включении:
   API rformContentApiV04EnableTrainingDrafts(), затем Bot rformOwnerBotV1EnableTrainingDrafts().
   Первый baseline запуск не должен создавать прошлые черновики.
7. Runtime acceptance без публикации: тестовый материал или отдельно разрешённая
   тренировка, edit/photo/review/save/hold/date/return/preview. Не нажимать «Согласовать».
   Обязателен canonical readback и audit correlation для каждого перехода.
8. Проверить следующий реальный автоматический опрос и доставку нового черновика
   с совпадающим source fingerprint. Только после этого считать автоматизацию установленной.

Rollback: выключить training sync в обоих проектах, вернуть API 0.5.7/Bot 1.0.5
в предыдущие deployment versions. Сохранить canonical историю и файлы. Не удалять
новые черновики; требующие дальнейшего решения сохранить/отложить штатным переходом.

## Открытые вопросы приёмки

- ИИ: подключённый исполнитель отсутствует; подготовлен только безопасный request/proposal путь.
- Runtime новой версии не проверен до её отдельной установки.
- Staged файлы отменённых/истёкших правок остаются приватно в Drive. Автоудаление
  не добавлено; очистка требует отдельного согласованного retention правила.
- Доставка напоминаний at-most-once: неопределённый исход требует ручной диагностики.
- Задержки Google Apps Script / signed read, наблюдавшиеся ранее, не устранены этим релизом.
