## Этап 1: стабильность

- Poll изолирует сверку, создание тренировочных черновиков, чтение, напоминания, ИИ-предложения и каждый предпросмотр. Число попыток предпросмотра ограничено шестью за запуск; курсор проходит очередь по кругу, чтобы повреждённые материалы не блокировали последующие. Ошибка одного этапа не останавливает независимые этапы. Ошибка чтения помечает зависимые этапы как пропущенные.
- Сохраняются отчёт последнего запуска, итог OK/PARTIAL/ERROR, время полного успеха и свежесть данных. /status читает их без загрузки всей очереди. Успешное завершение Apps Script само по себе больше не принимается за успешный workflow.
- Подписанный read_owner исключает события и тренировочные сессии из чтения ботом. Полный read остаётся совместимым с Control. Подписи различают операции; непроверенные редиректы не разрешены. Автоматического повторения POST нет.
- Новый подписанный action_status читает существующий CONTENT_ACTION_LOG по Action_ID и Content_ID. Ничего не изменяет. APPLIED означает наличие подтверждённой записи об операции, а не отсутствие последующих изменений материала.
- После потери ответа на изменение карточки Bot/Control проверяют receipt. Подтверждённый APPLIED восстанавливает результат; PENDING/NOT_FOUND/OUTCOME_UNKNOWN сохраняют ID и блокируют следующее изменение карточки в этом интерфейсе. /status либо кнопка проверки выполняют только чтение. Отказ API по бизнес-правилу не выдаётся за неизвестную операцию.
- Фоновые многострочные операции, загрузка фото, чтение версий и существующий approval flow сохраняют свои прежние проверки. Проверка receipt не заменяет их readback и не повторяет их запросы.
- getChatMember использует строковый user_id, как в успешной производственной проверке.

## Этап 2: интерфейсы

- Один контракт разделов в Bot/Control, покрытый общей JSON-матрицей: PUBLISHED выше архивных маркеров; архив выше HOLD; Publication_Status HOLD или Pipeline_Status HOLD/ПАУЗА — «Отложено»; остальные незакрытые материалы — «В работе». Старые строки не переписываются.
- Для старых строк с Pipeline_Status HOLD доступны возврат и напоминание. Предпросмотр отложенного материала блокируется. Дата возврата не является датой публикации.
- «Сверка» считает только посты с кандидатами. Несвязанные исторические сообщения остаются в истории и не требуют массового отклонения. Автоматическое сопоставление продолжает использовать прежнее строгое правило; неоднозначные связи требуют сравнения.
- Bot ищет по полному тексту, Content_ID, Session_ID, рубрике, датам, номеру и URL поста. Поиск включает самостоятельные наблюдения канала, не меняя статусы исходных строк. Пагинация сохраняет запрос.
- Control предлагает «В работе», «Отложено», «Опубликовано», «Архив», «Все». Поиск материалов расширен, история канала имеет отдельный поиск. Для опубликованного материала дата берётся из Posted_At, если он заполнен.
- Карточка объясняет следующий шаг. Заголовок приложения описывает реальные возможности; автоматический ИИ-исполнитель пока не подключён.

## Оставшиеся ограничения и приёмка

- Первичная причина второго редиректа Google ContentService остаётся неподтверждённой. Уменьшен объём чтения ботом и изолированы последствия; устранение сетевых сбоев не заявляется. Нужны измерения после установки.
- Получены отдельные production-измерения выше; требуется наблюдение нескольких автоматических циклов. Старый полный read приложения сохранён.
- PENDING/NOT_FOUND/OUTCOME_UNKNOWN не дают права повторить запись автоматически. Нужна проверка журналов и текущей строки оператором; интерфейс не содержит обхода блокировки.
- Pending-ID в Control хранится в текущей Streamlit-сессии; /status бота использует ScriptProperties. После закрытия сессии Control ID остаётся в сообщении ошибки и существующем журнале, если операция дошла до API.
- Приёмка на физическом телефоне и новая закрытая тренировка после baseline ещё не выполнены. Desktop-интерфейс и живые подписанные запросы проверены. Искусственные производственные тренировки не создавались.
- Этап 3 (семантика закрытия тренировки, автоматический ИИ-исполнитель, редакционные disposition) и контент-аналитика не входят в этот кандидат.
